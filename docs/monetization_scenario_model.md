## 使い方

```bash
npm run model:revenue -- docs/monetization_model.example.json
# または
node scripts/monetization-scenario.mjs docs/monetization_model.example.json
```

入力JSONのコピーを作り、実測または明示した別シナリオの値に変更してください。出力は計算上の月額収益、広告の請求対象と仮定する表示回数、想定固定/変動費、想定損益分岐MAUを含みます。値の単位は円/月（`monthlyActiveUsers`と表示回数を除く）です。

## サブスクの前提

Asana「サブスク用の基盤を整える」にある**税込予定価格**のみを固定値として使用します。

| 予定プラン | 月額 | 年額 |
|---|---:|---:|
| Plus | 300円 | 3,000円 |
| Premium | 550円 | 5,000円 |

- `subscriberShares` はMAU全体に占める各プランの有料加入者比率。年間契約者は契約済み人数に基づく想定比率です。Free・有料者・試用中利用者の比率の合計が100%を超えないように検査します。
- `activeTrialShare` は無料体験中で広告非表示、売上は発生しないものとして扱います。二重計上はしません。
- 年額支払は年額÷12で月次収益に配分します。**キャッシュフロー予測ではなく月次の概算**です。実際の入金月や返金、税務会計とは異なります。
- サブスク粗売上（税込）を `1 + consumptionTaxRate` で割り、仮定の返金率、決済手数料率、1決済当たりの固定手数料を引いて、処理後の月額純収益を計算します。手数料は税込決済額を基準と仮定。年額契約の決済手数料も÷12して月次配分。
- 予定価格は税込です。消費税・手数料・返金率・販売開始可否は実運用時点で確認してください。

## 忍者AdMaxの前提と式

**MAUは広告表示回数でも広告到達人数でもありません。** 有料Plus/Premium・トライアルの加入者には広告を表示しないものとして計算します。

```text
Free MAU = MAU × (1 - 有料各プラン比率の合計 - トライアル比率)
広告表示候補 = Free MAU × 一人当たり月のホーム訪問回数 × 1訪問当たり候補広告枠
広告要求候補 = 広告表示候補 × 枠が成立する率 × (1 - 広告ブロック率)
請求対象と仮定する表示回数 = 広告要求候補 × fill率 × billable率
広告収益（想定） = 請求対象と仮定する表示回数 / 1000 × 配信者手取りeCPM
```

- `publisherNetEcpmYen` は**円換算後の発行者手取り（実質eCPM）を仮定する値**で、広告主の出稿単価、忍者AdMaxが保証するレート、Google AdSenseの単価ではありません。忍者AdMaxの公式利用規約では、広告表示・クリックに応じて「忍者ツールズポイント」を付与する仕組みです。管理画面のポイント数をそのまま円として入力しないでください。実際の交換可能額、交換条件・手数料と対象期間の実配信数を確認し、「円換算した発行者手取り額 ÷ 対象表示回数 × 1,000」で実質eCPMを計算します。表示数が0の場合は算出できず、推定値を実績と表示しません。公式規約: https://www.ninja.co.jp/rule/admax
- 実際の請求基準は広告ネットワークのレポートに従います。`billableRate` は実際の請求対象率を表す仮パラメータです。閲覧可能性と必ずしも同義ではありません。
- `possibleAdSlotsPerHomeVisit` は**平均候補表示枠数の仮定**です。アプリで現在許可している広告枠数の上限や、Ninja広告配信元で実際に供給される表示数ではありません。
- `inventoryReadyRate` は隣接するジャンルの有無やタイムライン投稿数などにより実際に枠が描画され得る割合。`fillRate`、ブロック率も推定値でなく実測が必要です。
- 直販広告は未承認・未販売のため売上計算から除外。アフィリエイト収益も正式稼働前のため除外。

## 損益分岐点

```text
月次固定費 = fixedMonthlyCostsYen
MAUあたり変動費 = variableMonthlyCostsPerMauYen
MAUあたり限界利益 =
  (各有料加入比率 × 税抜月次配分単価 - 想定手数料/返金)
  + (Free比率 × 広告実表示前提 × ネットeCPM/1000)
  - MAUあたり変動費
損益分岐MAU = ceil(月次固定費 / MAUあたり限界利益)
```

固定費が0なら損益分岐MAUは0、限界利益が0以下かつ固定費が正なら達成不可（`null`）です。**加入比率・アクセス頻度・単価・運営費がMAUに対して一定**という仮定の下でのみこの線形計算が成り立ちます。広告需要・表示品質・手数料・インフラ段階課金は必ずしも線形に増減しません。

## 実測値に置き換える際の収集元（管理者のみ・秘密情報は保存しない）

| 必要な入力 | データ源の例 |
|---|---|
| MAU / ホーム訪問数・端末別 | 将来導入する同意・開示に合う利用分析（現時点でFirebase/GA4がない場合は未測定） |
| 広告の有効表示・fill・発行者収益 | Ninja AdMax管理画面の実測レポート |
| 無料・有料・トライアル割合 | Supabase上の契約状態の集計（個人データをファイルへ書き出さない） |
| 決済手数料・返金・税 | 決済事業者の契約、請求書、返金記録 |
| インフラ固定/変動費 | Vercel、Supabase、ドメイン等の月次請求 |
| 人件費・サポート・会計法務費 | 運営側の実績/計画 |

実績未取得の項目がある間はAsana「広告収益の見積もり」「損益分岐点の計算」は**暫定モデル作成済み・実測入力待ち**として扱ってください。
