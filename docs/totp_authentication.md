# Sharemarium TOTP（二段階認証）運用手順

## 実装範囲

- 新規登録では、公開プロフィールと個人情報変更用パスワードの登録後に認証アプリのQRコードを表示する。
- 既存利用者も、次回利用時に認証アプリの登録を求める。
- Google又はXでログインした後、登録済みTOTPがある場合は6桁コードを確認する。
- 個人情報変更用パスワードの再設定は、同じOAuth providerでの再認証とTOTP確認の両方を必要とする。
- 個人情報変更用パスワードの再設定画面で6桁コードを5回誤入力すると、当該再設定だけを24時間ロックする。通常画面の閲覧は継続できる。
- 認証端末を紛失した利用者は、個人情報変更用パスワードを確認した上で既存要素を解除し、新しいQRコードを登録する。
- パスワードも利用できない場合は、お問い合わせの「認証用QRコードの再取得」で本人確認を申し出る。
- 管理者解除にはAAL2、管理者権限、管理者追加パスワード、10文字以上の理由及び受付番号を必要とし、許可・完了又は失敗を追記専用監査ログへ記録する。

TOTPの設定キー及び6桁コードはアプリケーションDB及び監査ログへ保存しない。

## 安全な反映順序

クライアントを先に公開するとログイン画面が新しいEdge Functionを呼べないため、次の順序を守る。

1. stagingでマイグレーションを適用する。
2. stagingへ`totp-recovery` Edge Functionを配置する。
3. stagingクライアントを配置し、登録、通常ログイン、OAuth後のパスワード復旧、5回ロック、自己再登録及び管理者解除を確認する。
4. 本番マイグレーションを手動承認して適用する。
5. 本番へ`totp-recovery` Edge Functionを手動承認して配置する。
6. その後に本番Flutterクライアントを公開する。

本番DB及びEdge Functionは、通常のpushでは自動適用しない。

## iPhoneの「パスワード」について

QRコードを読み取っただけで、すべての端末・アプリへ自動登録されるわけではない。iOSの対応画面から読み取った場合は「パスワード」への追加候補が表示されることがあるが、Google Authenticator等では利用者が各アプリ内で追加操作を行う。Sharemariumは登録完了後に秘密のQRコードを再表示せず、再取得時は古い要素を無効化して新しい要素を発行する。
